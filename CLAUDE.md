# CLAUDE.md

Guidance for Claude Code when working in this repository.

Structure and several of the conventions below are adapted from the `CLAUDE.md`
Christopher wrote for `robot-curiosity/ROS-2-Repository`. The constraints in
"Conventions" were previously only recorded inside
`docs/superpowers/plans/2026-07-30-behaviour-coordinator.md`, which will stop
being read once that plan is finished; they belong here.

## What this is

Autonomous outdoor litter collection: a four-wheel skid-steer base with an
SO-101 arm, navigating without a map or LIDAR. ROS 2 **Jazzy**, Gazebo
**Harmonic**, Raspberry Pi 5 target.

**Read [`docs/STATUS.md`](docs/STATUS.md) first** — state, measured figures,
known issues, decisions not worth relitigating, and a table of gotchas every one
of which failed *silently*.

| Package | |
|---|---|
| `drivebase_description` | URDF, frame tree, Gazebo plugins and sensors |
| `so101_description` | SO-101 arm, vendored upstream, mountable macro + `ros2_control` |
| `drivebase_sim` | Gazebo world, bridge, sensor shims, measurement rig |
| `drivebase_localization` | Local + global EKF, `navsat_transform` |
| `drivebase_navigation` | Nav2: RPP controller, ultrasonic costmaps |
| `drivebase_msgs` | `LitterDetection` typed interface |
| `drivebase_behaviour` | Mission coordinator: pure logic + a thin ROS shell |
| `trash_vision` | YOLO litter detector (**separate author**) |

## Environment

**Everything runs through `scripts/dev.sh`**, which builds the container on
first use and wires up the GPU and display. A bare `ros2` or `colcon` on the
host will fail with "command not found".

```bash
bash scripts/dev.sh colcon build --symlink-install
bash scripts/dev.sh ros2 launch drivebase_sim sim.launch.py rviz:=true
bash scripts/dev.sh                      # interactive shell, workspace sourced
bash scripts/dev.sh --reset              # drop the build volumes
```

- **Always `--symlink-install`, never a bare `colcon build`.** Mixing the two
  corrupts the build tree in a way that is not confined to the package you
  rebuilt. Recover with `rm -rf build/<pkg> install/<pkg>` and rebuild.
- `build/`, `install/` and `log/` are **Docker volumes, not directories in the
  repo**. The repo sits on an NTFS/fuseblk mount that silently drops the
  executable bit, so console scripts would install non-executable.
- The pure-geometry work (kinematics, detection, localisation) needs no ROS at
  all — see `scripts/dev-native.sh`.

## Verifying things

- **Never verify a topic with `ros2 topic echo --once`.** Each CLI invocation is
  a fresh node and it intermittently fails to discover a low-rate publisher
  before giving up, reporting a *working* bridge as broken. Use one long-lived
  `rclpy` node that subscribes and spins for ~25 s.
- **One container per `scripts/dev.sh` call.** Background processes do not
  survive between calls, so anything that launches the simulator and then
  queries it must be a single `bash scripts/dev.sh bash -c '... & sleep 25;
  ...'` invocation.
- Allow **~20–25 s** for Gazebo to come up.
- This machine has a real GPU and `dev.sh` passes `/dev/dri` through. It falls
  back to llvmpipe only when there is none — and under llvmpipe, **trust
  geometry, never timing.** Any figure in Hz or "how long did it take" measured
  that way is worthless.

## Conventions

- **Do not modify `src/trash_vision/`.** It belongs to another author.
- **Do not hand-edit `so101_description/urdf/so101_macro.xacro`.** It is
  generated by `scripts/vendor_so101.py`. To pick up an upstream change,
  replace `urdf/so101_upstream.urdf` and re-run the script.
- **Never invent physical parameters** — masses, inertias, joint origins, axes,
  limits, mesh dimensions. Import them from a trustworthy source or leave them
  out. Do not fabricate a value to silence a Gazebo warning.
- **Never hardcode a figure that can be derived.** Arm link lengths come from
  the URDF at runtime. Measured values go in a params YAML, not in source.
- **Pure logic must not import `rclpy`.** `detection.py`, `localisation.py`,
  `kinematics.py`, `ik.py` and `state_machine.py` import only the standard
  library and `numpy`. That is what makes the whole mission testable in
  milliseconds with no simulator. A test needing `rclpy.init()` means the
  boundary was crossed.
- **No new heavy runtime dependencies.** The Pi 5 shares cores with YOLO. No
  MoveIt, no py_trees, no SMACH.
- **Comments explain WHY, not WHAT.** Match
  `drivebase_sim/drivebase_sim/laserscan_to_range.py`. No docstrings that
  restate a function name.
- 4-space indent. **Do not add `test_flake8.py` / `test_pep257.py` stubs** —
  this repo's own packages declare the lint deps without the test files, and
  adding them fails the build on ament's quote preference and on `D103`.
- Keep changes small and reviewable.

## The arm

Three xacro files with separate jobs — preserve this split:

| File | Job |
|---|---|
| `so101_macro.xacro` | geometry/kinematics only; **generated** |
| `so101.ros2_control.xacro` | hardware plugin + interfaces; `use_gazebo` switch |
| `so101.urdf.xacro` | standalone composition: `world` link, launch args |

**There are two arm control paths, and they are not interchangeable:**

- **On the drivebase** — six gz `JointPositionController` plugins taking
  `std_msgs/Float64` on `/arm/<joint>/position`, bridged in
  `drivebase_sim/config/bridge.yaml`. This is what `drivebase_behaviour`'s
  `arm_driver.py` drives, and it maps directly onto the Feetech STS3215 bus on
  hardware.
- **Standalone** (`so101_description`'s own launch files) — `ros2_control` with
  a `JointTrajectoryController`, either `mock_components/GenericSystem` or
  `gz_ros2_control/GazeboSimSystem` behind `use_gazebo`.

Run exactly one `robot_state_publisher` and one controller manager at a time;
never combine `bringup.launch.py` and `gazebo.launch.py`.

**The `arm_` prefix is load-bearing.** The macro namespaces every link and
joint and the drivebase instantiates it as `prefix="arm_"`. A controller config
with bare joint names spawns, reports `active`, and moves nothing — with no
error on either side.

`/joint_states` orders joints **alphabetically**, not as listed in any YAML.

## The one thing to know before building on this

**Turns, not distance, dominate position error** — ~0.35 m per 90°, while 20 m
of straight driving costs essentially nothing. Two turns put the base ~0.7 m
off, far larger than a piece of litter. The arm has to be aimed by the camera
closing its own loop, **never by driving to a coordinate.**
